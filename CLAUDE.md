# CLAUDE.md

Правила работы над проектом. Описание продукта и запуск - в [README.md](README.md).

## Стек

React 19, TypeScript, Vite, ESLint, Prettier, Vitest. Менеджер пакетов - pnpm. Нужен Node ≥ 20.

## Структура (Feature-Sliced Design)

Слои сверху вниз: `app` → `pages` → `widgets` → `features` → `entities` → `shared`. Слой импортирует только нижележащие; слайсы одного слоя не импортируют друг друга. Публичный API слайса - `index.ts`, импорт через алиас `@/`. Внутри слайса сегменты: `ui/` (компоненты), `model/` (логика, типы, хуки, тесты), `config/` (константы). Константы не кладём в `ui/`.

- `src/app/` - точка входа, глобальные стили (SCSS) и токены дизайна.
- `src/pages/` - страницы (композиция виджетов).
- `src/widgets/` - самостоятельные блоки интерфейса (`todo-board`).
- `src/features/` - пользовательские сценарии (`add-todo`, `filter-todos`, `edit-todo`, `reorder-todos`, `clear-completed`, `toggle-theme`).
- `src/entities/` - доменные сущности (`todo`: типы, операции, zustand-стор с persist).
- `src/shared/` - `ui/` (переиспользуемые UI-компоненты), `lib/` (общие хелперы), `assets/icons/` (SVG-файлы; в код попадают компонентами через SVGR: `import { PlusIcon } from '@/shared/assets'`); без знания о домене.

## Принципы

- Небольшие компоненты с одной ответственностью; логика отдельно от представления.
- UI-компоненты переиспользуемы и не импортируют доменный код.
- Минимум зависимостей: не добавлять пакеты и не менять архитектуру без необходимости.

## Компоненты и функции

- Каждый компонент - отдельная папка: `Name/Name.tsx`, `Name/Name.scss`, `Name/index.ts`.
- Функции и компоненты объявлять через `const` (стрелочные), без `function`.
- Без комментариев в коде, если они не необходимы; названия тестов - на русском.

## TypeScript

- Никакого `any`; `unknown` + сужение типов для внешних данных (localStorage).
- Явные типы для публичных интерфейсов (props, возвращаемые значения экспортируемых функций).
- Без небезопасных приведений (`as`, `!`) - использовать type guards.

## React

- Только функциональные компоненты и хуки.
- Не дублировать состояние: производные значения вычислять, а не хранить.
- Зависимости эффектов указывать корректно, не подавлять `react-hooks/exhaustive-deps`.

## UI

- Семантический HTML, доступность с клавиатуры, `aria-*` где нужно.
- Состояния hover / focus-visible / active / disabled у всех интерактивных элементов.
- Адаптивность (mobile first проверка ≤ 480px); анимации уважают `prefers-reduced-motion`.

## Тесты

Тестируем бизнес-логику и критические сценарии (операции, фильтры, валидация, хранилище, повреждённые данные), а не детали вёрстки.

## Перед завершением изменений

Обязательно запустить и добиться успеха: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`.
